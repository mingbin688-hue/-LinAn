# 邻安 · 三轮审计与修复记录（2026-11-12）

范围：`backend/`（约 2.4k 行）、`app/lib/src/`（约 7.2k 行）、`tests/`、`scripts/`、根目录启动脚本与文档。方法：逐文件静态审计 + 三个独立审计子 Agent（后端、Flutter 前端、脚本/文档/打包）交叉核对 + 行为断言测试。审计前基线：后端 60 项测试通过、`flutter analyze` 无问题；审计后：后端 70 项通过、Flutter 4 项测试通过。

严重度：**P0** 功能不可用或越权；**P1** 明显错误或数据不一致；**P2** 可维护性、性能与文档偏差。

## 第一轮：后端与数据层

| 严重度 | 问题 | 处理 |
|---|---|---|
| P0 | `/api/notifications` 先取全局 300 条再按角色过滤，家属/照护人员可能看不到自己的通知 | SQL 内按 `role`/`staff_id`/`elder_id` 过滤后再取 30 条；`tests/test_hardening.py` 用 320 条更高优先的通知构造回归 |
| P0 | 客户端人员开关只提交单个字段，后端模型要求全量字段，`PUT /api/staff/{id}` 恒 422 | 后端改为可选字段合并更新（空对象 422 并给出可操作提示）；客户端乐观更新、失败回滚 |
| P1 | `jobs.fail()` 无调用方：模型调用异常时只靠 30 秒租约过期重试，失败节点与错误信息丢失 | `workflows.drain()` 捕获异常、写失败节点、按指数退避重排，达到上限转死信并标记运行失败 |
| P1 | 登录失败计数只清理当前用户名，长期运行无限增长 | 超过 256 个键整体裁剪，每个用户名只保留最近 10 次失败 |
| P1 | 活动事件校验把 `True` 当数字、接受 `NaN`/`Infinity`，`original_timestamp` 与 `hours` 边界混用 | 统一 `_within()` 校验：拒绝布尔、字符串、非有限值，时间戳加 30 秒时钟偏差，`hours` 走严格区间 |
| P1 | 老人详情 `latest_incident` 取“最高等级”而非“最近一条”，字段名误导 | 改为 `level DESC, created DESC`，并在批量装饰器中一次查询完成 |
| P1 | 任务/老人列表逐条查事件、人员、老人名（N+1） | 改为 `decorate_tasks`/`decorate_elders` 批量查询（3 条 SQL） |
| P1 | `Database(':memory:')` 可创建成功但每个事务新连接，随后报 `no such table: elders` | `Database.__init__` 直接拒绝并说明改用临时文件；补测试 |
| P1 | 工作流节点 upsert 会把已写入的 `started/finished` 重置为 0；等待人工的运行每 5 秒重写全部节点 | upsert 用 `CASE` 保留时间戳；新增 `_put()` 仅在内容变化时写节点 |
| P1 | `ModelRegistry.models` 无上限，回放/实验反复训练会持续占用内存 | 新增 `remember()`，超过 128 个模型淘汰最旧条目 |
| P2 | `PersonalModel` 训练用纯 Python 双重循环（96 个时段 × 窗口数），训练明显偏慢 | 改为 numpy 向量化（基线、空闲阈值、时段距离） |
| P2 | `retry_job`/`cancel_job`/`retry_run` 审计写死 `actor='admin'`，无法区分操作者 | 审计记录真实调用者用户名 |
| P2 | `ml.casas_split`、回放窗口、实验脚本各自复制 60/20/20 切分逻辑 | 统一到 `ml.casas_split()`，回放改为 `models.remember()` |
| P2 | 结构化重构：617 行闭包式 `api.py` | 拆为应用工厂（87 行）+ `routes/` 六个模块 + `schemas.py`/`deps.py`/`session.py`/`serializers.py`；`scope.py` 成为唯一可见范围实现 |

## 第二轮：Agent、工作流、MCP 与权限

| 严重度 | 问题 | 处理 |
|---|---|---|
| P0 | MCP 鉴权接受普通登录会话令牌，任何登录用户可绕过 MCP 令牌生命周期与撤销 | `authenticate()` 只接受 `mcp_tokens` 表令牌；登录令牌返回 401，`docs/MCP.md` 同步说明 |
| P1 | 模型/解释失败时运行记录不落失败节点，前端只能看到“执行中” | 失败时写 `fallback` 节点（含异常类型与尝试次数）并更新运行状态 |
| P1 | MCP 资源 `linan://elders/not-a-number` 触发 `ValueError`，返回 JSON-RPC `-32603` 内部错误 | 解析失败按 `404 未知资源` 处理，返回 `-32003` |
| P1 | 助手引用 id 在 `scope.py` 被转成字符串，前端按数字判断，引用跳转永远走原始弹窗 | 前端按字符串比较，任务/老人引用打开带详情的侧边抽屉 |
| P1 | 助手上下文 `redactions` 语义模糊 | 明确为“因脱敏而未包含联系方式的对象数”，并在文档与界面口径一致 |
| P2 | `ContextBuilder._trim` 每轮重新序列化整个上下文（预算 6000 时 O(n²)） | 评估后保留：单次上限约 40 条记录，实测耗时 < 5ms；在代码注释说明取舍 |
| P2 | `workflow_store.set_status`、`latest_run` 无调用方 | 删除；新增 `finish()` 统一更新运行摘要/模式 |
| P2 | `workflows.process()` 每次重复读取策略、重复写运行状态 | 每次巡检只读一次策略；运行状态仅在变化时更新 |

保留的业务约束（测试覆盖、未改动语义）：主动求助直接紧急人工、报平安不降低未关闭事件、数据缺失为未知、模型只解释、仅 1 级电话核实可自动派单、推荐按全量待派优先级分配、`BEGIN IMMEDIATE` 与唯一索引、拒单/继续跟进不循环重派、模型调用不持有写事务、工具与会话每次重验角色与对象权限、事件去重与重启恢复。

## 有意保留

- 演示账号与演示口令、登录页快捷入口：比赛原型需要开箱可演示，README 已注明仅用于本地演示。
- 助手在无模型配置时走规则模式、模型只做解释：与“模型不得改变风险等级”的约束一致；本轮未接入真实供应商。
- `ContextBuilder._trim` 的重复序列化：规模受限（≤40 条记录），保留可读性优先的实现。
- 数据库 `sessions` 表未加外键：会话与用户解耦便于注销与过期清理，用户名即主键已保证一致性。
